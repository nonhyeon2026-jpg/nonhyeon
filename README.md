# 논현동 재개발구역 지도

서울 강남구 논현동의 재개발 / 공공재개발 / 모아타운 구역을 **지번(필지) 단위**로 지도 위에 표시하고,
관리자가 필지를 구역에 편입하거나 제외할 수 있는 웹앱입니다.

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- **배경지도**: 네이버 지도 JS API v3 (지적편집도 레이어 포함) — 키가 없으면 Leaflet + OSM 으로 자동 대체
- **필지 도형**: VWorld 연속지적도 (`LP_PA_CBND_BUBUN`)

> 네이버 지도는 필지 폴리곤 **좌표**를 제공하지 않습니다. 지적편집도는 그림(래스터)이라
> 클릭·색칠이 안 되므로, 도형은 VWorld에서 받아 네이버 지도 위에 얹는 구조입니다.

## 실행

```bash
npm install
cp .env.example .env.local     # 키를 채웁니다 (없어도 실행됩니다)
npm run dev                    # http://localhost:3000
```

키가 하나도 없어도 샘플 필지 + OSM 지도로 모든 기능이 동작합니다.
헤더의 데이터 출처 표기가 **주황색(샘플)** 인지 **초록색(VWorld)** 인지로 현재 상태를 알 수 있습니다.

## 인증키 발급

| 키 | 용도 | 발급처 |
| --- | --- | --- |
| `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID` | 배경지도 | [NCP 콘솔](https://console.ncloud.com/naver-service/application) → Maps → Application 등록 → **Web Dynamic Map** 이용신청 |
| `VWORLD_KEY` | 실제 지적도 임포트 | [VWorld](https://www.vworld.kr) → 오픈API → 인증키 발급신청 (**데이터 API**) |

- NCP에서 **Web 서비스 URL** 에 `http://localhost:3000` 을 등록해야 지도가 뜹니다. 누락되면 화면에 안내 메시지가 나옵니다.
- 인증 파라미터 이름은 발급 시점에 따라 다릅니다. 신규 키는 `ncpKeyId`(기본값), 예전 키는 `ncpClientId` — `NEXT_PUBLIC_NAVER_KEY_PARAM` 으로 바꿉니다.
- VWorld 키는 서버 스크립트에서만 쓰이므로 브라우저로 노출되지 않습니다.

## 건물 정보 (건축물대장)

```powershell
$env:BLDRGST_KEY="키"
npm run import:bldrgst    # 지번별 표제부 조회 → public/parcels.json 병합
```

국토교통부 건축물대장 표제부(`BldRgstHubService/getBrTitleInfo`)를 **지번(본번/부번)으로 직접**
조회합니다. 공간조인이 필요 없어 건물–필지 대응이 정확합니다. 붙는 값:

- 주용도 + **다세대 / 다가구 / 연립 / 아파트 세부 유형** (`etcPurps` 에서 추출)
- **세대수 / 가구수 / 호수**
- 층수, 연면적, 사용승인일(노후도), 구조, 건폐율·용적률

주의할 점:

- data.go.kr 은 **초당** 요청 제한이 있습니다. `PER_SECOND` 오류는 재시도 대상이고
  일일 한도 초과만 중단 사유입니다. 요청 간격 120ms + 동시 2로 5,500건을 실패 없이 받습니다.
- 응답은 `data/bldrgst-cache.json` 에 저장돼 중단돼도 이어받습니다. 다시 받으려면 이 파일을 지우세요.
- VWorld 건물정보(`scripts/import-buildings.mjs`)도 남겨뒀지만 **용도 정확도가 떨어집니다**
  (표본 10건 중 9건이 대장과 불일치). 세대수도 없습니다. 건축물대장을 쓰세요.

## 용도지역

```powershell
$env:VWORLD_KEY="키"
npm run import:zoning     # VWorld 용도지역(LT_C_UQ111) 공간조인 → public/parcels.json 병합
```

필지마다 `zoning`(제2종일반주거지역 등)을 붙입니다. 중심점 한 점이 아니라 필지 안에 격자로
찍은 표본점으로 면적 비율을 어림해, 경계에 걸친 필지는 넓은 쪽을 `zoning` 으로 두고 비율을
`zoningMix` 에 남깁니다. 표본 대조에서 한 용도지역 필지 20건은 토지이용계획(`getLandUseAttr`)과
전부 일치했고, 걸친 필지는 토지이용계획에도 두 용도지역이 "저촉"으로 함께 나옵니다.
레이어에 이름(`uname`) 없는 큰 도시지역 폴리곤이 겹쳐 있어 이름 없는 폴리곤은 버립니다.

참여의향서 레이어에서 **제출이 없는 구역 필지**는 1종(파랑)·2종(빨강)·3종(주황)으로 색을
나눕니다. 제출이 있는 필지는 용도지역과 상관없이 제출률 색 그대로입니다.
`import:vworld` 로 필지를 새로 받으면 이 값이 사라지므로 다시 돌리세요.

## 동의율

구역 요약 카드에 두 가지 비율을 나란히 둡니다.

- **참여의향서 제출률** = 낸 사람 수 / 소유자 수. 호가 아니라 사람으로 셉니다 — 통건물 제출은
  전 호가 동의여도 1명입니다. 분모는 관리자 모드에서 구역마다 넣은 총 소유자 수가 있으면 그 값,
  없으면 아래 **추정 소유자 수**입니다. 카드에는 호수 기준 비율도 참고로 함께 적습니다.

### 추정 소유자 수

건축물대장 호수 합계는 다가구·통건물을 호마다 세어 소유자보다 크게 나옵니다. 그래서 필지마다
(`parcelOwners`) 이렇게 셉니다.

| 필지 | 소유자 |
| --- | --- |
| 집합건축물 — 토지소유정보가 있으면 | 호별 소유 변동으로 묶은 수 (`building.owners`) |
| 집합건축물 — 없으면 | 구분소유 호수 (`building.collective`) |
| 명부에 통건물 제출(`-`)로 올라온 필지 | 1명 |
| 일반건축물(단독·**다가구**·근생·업무 등)·빈 땅 | 1명 — 가구가 여럿이어도, 땅을 공동명의로 가져도 1명 |
| 그중 한 땅에 주건축물이 여러 동인 필지 | 동마다 1명, 땅 공유자 수(`land.owners`)를 넘지 않게 |
| 건물 없는 국공유지 (땅 전체가 국유지·시도유지·군유지, `land.public`) | 0명 — 205-7 국유지 공원 |

일반/집합은 표제부의 `regstrGbCdNm` 으로 가릅니다. 집합 공동주택 표제부는 세대수가 주거 호,
호수가 그 밖(1층 근생 등) 호라 둘을 더합니다(세대 12 · 호 1 → 13). 토지소유정보와 대조하면
둘 다 적힌 동 중 148곳이 합계와, 11곳이 세대수와 맞았습니다.
명부의 제출 인원이 추정보다 많으면 제출 인원을 따릅니다. 거꾸로 한 사람이 여러 호를 낸
필지(`unitGroups`)는 소유자가 **낸 사람 + 안 낸 호 수** 를 넘을 수 없어 그 값으로 줄입니다 —
173-2 는 3명이 12호를 다 내서 6명이 아니라 3명, 172-1 은 7명이 11호를 내고 3호가 남아 14명이 아니라 10명.

#### 토지소유정보로 한 사람이 가진 호 묶기

```powershell
npm run import:possession   # .env.local 의 VWORLD_KEY 로 집합건축물 필지만 조회
# 또는 node --env-file=.env.local scripts/import-possession.mjs
```

VWorld `ned/data/getPossessionAttr` 는 이름 없이 **호마다** 개인/법인, 소유권 변동 원인·날짜,
거주지 구분을 줍니다(기준월 `stdrYm`, 실시간 등기 아님). 집합건축물이 아닌 필지는 호 행 없이
땅 소유자가 사람마다 한 줄씩 나오므로 그 수를 땅 공유자 수(`land.owners`)로 둡니다.
**공동명의는 1명**으로 셉니다(집합건축물 한 호의 공유자도 1명). 다만 153-1 처럼 단독·근생
11개 동이 앉은 땅을 18명이 지분으로 나눠 가진 필지는 동마다 주인이 따로라 1명이면 크게
모자랍니다. 그래서 주건축물 동 수(`building.mainCount`, 부속건축물 제외)와 땅 공유자 수 중 작은
쪽을 씁니다(153-1 → 11명). `import:bldrgst` 를 다시 돌리면 `building.owners` 가 지워지므로 그 뒤에
`import:possession` 을 다시 돌리세요(캐시만 씁니다). 집합건축물은 이렇게 묶습니다.

- **통건물**: 전 호가 같은 날 같은 원인 — 지은 채 안 판 건물(보존등기), 통째로 산 건물(이전).
  분양은 호마다 날짜가 흩어집니다.
- **일부 묶음**: 같은 날 보존등기한 채 남은 호들(건축주가 안 판 호), 같은 날 주소·이름을 고친
  호들은 개인/법인·거주지 구분까지 같으면 한 사람입니다. 같은 날 소유권이전은 분양일 수 있어
  묶지 않습니다.
- **확인 필요**(`check`): 같은 날 보존·이전인데 거주지 구분이 갈린 필지 — 공동건축주가 호를 나눠
  가졌을 수 있습니다. 정부24 건축물대장 열람으로 확인하세요.
- 한 호의 공유자는 1명. 대지권 미등기라 호 행이 없는 필지는 대장 호수를 씁니다. 한 건물이 두
  지번에 걸쳐 같은 호 목록이 나오면 앞 지번만 셉니다(`sameAs`).
- 소유정보상 통건물인 필지는 명부에 호를 나눠 적었어도 낸 사람을 1명으로 셉니다.

명부의 통건물 표기 8곳 중 7곳이 이 규칙으로 통건물로 나왔습니다(174-17 은 공유자 쌍의
주소변경 날짜가 갈려 3명). 같은 사람이 날짜를 달리해 여러 호를 사 모은 경우는 여전히 알 수
없어 따로 셉니다. 원자료 `data/possession-cache.json` 은 호별 변동 내역이라 커밋하지 않습니다.

`collective` 는 `import:bldrgst` 가 캐시에서 다시 만들므로 키 없이 캐시만으로 다시 돌려도 됩니다.

#### 구역 도로 쪼개기 점검

```powershell
npm run check:road-trades            # .env.local 의 land_key, 기본 2015-01 ~ 이번 달
npm run check:road-trades -- 202401  # 시작 달만 바꾸기
```

국토교통부 토지 매매 실거래가는 지번을 본번 첫 자리만 남기고 가립니다("1**" = 본번 100~199).
그래서 논현동 · 지목 도로 · 같은 용도지역 · 본번 자릿수 · 거래면적 ≤ 필지 면적으로 구역 안 도로
후보를 좁히고, 같은 달 같은 조건의 거래를 묶어 보여줍니다. 한 달에 작은 지분 직거래가 몰리면
쪼개기입니다. 거래 하나를 필지에 집지는 못하므로 토지소유정보의 땅 공유자 수·취득일
(`land.owners`, `data/possession-cache.json`)과 맞춰 보세요. 받은 달은 `data/land-trade-cache.json`
에 쌓이고(공개 자료, 이름 없음) 이번 달과 지난달만 다시 받습니다.

2026-10 점검: 구역 안 사유 도로 30필지(본번 131~188)는 취득일이 대부분 1977~1988년이고 "1**"
소액 지분 거래도 구역 것이 없어 쪼개기 흔적이 없습니다. 구역에서 1km 떨어진 242-8(사도
2,433㎡)은 2025-04 통째로 팔린 뒤 3.31㎡ 단위 지분이 수백 건 직거래됐습니다.
- **면적 동의율** = 한 호라도 제출한 필지의 면적 합계 / 구역 전체 필지 면적 합계.

면적은 호수와 달리 **필지 단위**로 셉니다. 다세대 한 동에서 한 호만 제출했더라도 그 필지
면적은 **전부** 동의 쪽에 들어갑니다 — 토지는 호마다 쪼개져 있지 않고 필지가 통째로 사업
대상에 들어가기 때문입니다. 같은 이유로 한 건물이 두 지번에 걸쳐 있으면(딸림 지번) 호수는
한 번만 세지만 면적은 두 필지를 각각 더합니다.

면적 요건은 1/2 처럼 경계가 딱 정해져 있어 49.6%가 50%로 보이면 안 되므로, 면적 동의율만
소수점 한 자리까지 표시합니다. 필지 면적은 `public/parcels.json` 의 `area`(폴리곤에서 계산한 ㎡)입니다.

### 새 명부로 보강하기

```powershell
npm run merge:consent -- nonhyun.xlsx "의향서 제출 최신본.xlsx"           # 바뀔 내용만 보여 준다
npm run merge:consent -- nonhyun.xlsx "의향서 제출 최신본.xlsx" --write   # DB 에 쓴다
```

앞이 DB 를 처음 만들 때 쓴 명부, 뒤가 새 명부입니다. **둘의 차이만** DB 위에 얹고 아무것도 지우지
않습니다. 이전 명부에 있던 호가 DB 에 없으면 관리자가 뺀 것으로 보고 다시 넣지 않습니다.
명부 읽기(`scripts/roster.mjs`)는 머리글에서 주소 열을 찾으므로 성명 열이 있든 없든 읽습니다.

- 한 칸에 적은 여러 호(`606, 1105호`)는 호마다 나눕니다. 예전 import 는 이것을 한 호로 넣어
  제출 호수를 적게 셌습니다(172-1: 7 → 11호).
- **한 사람이 낸 호**: 성명 열로 한 줄(또는 같은 지번의 같은 이름)이 낸 호를 묶어 `unitGroups` 에
  둡니다. 이름은 저장하지 않습니다. 제출 호수는 그대로 두고 **낸 사람 수**만 묶음마다 (호 수 − 1)
  줄입니다 — 205-2 의 `606·1105호` 는 2호 · 1명. 공동명의(`강민석, 박지은`)는 원래대로 1명입니다.
  관리자 화면에서 호를 지우면 묶음에서도 빠지고, 묶음은 필지 카드에 "한 사람이 함께 낸 호" 로 보입니다.
- 이전 명부에도 있던 호가 DB 에 없으면 넣지 않되 `!` 로 알립니다. 관리자가 뺀 호일 수도, 예전
  호 목록이 쪼개지며 잃은 호일 수도 있어서입니다 — 177-21 은 나동 201·202·301호가 이렇게 빠져
  있었습니다. 호를 알 수 없는 줄(`몇 호??`)도 호로 넣지 않고 알리므로, 낸 사람으로 세려면 관리자
  화면에서 `호수미상` 으로 넣으세요 (177-21 에 넣어 둠).
- 같은 이름이 여러 지번에 나와도 합치지 않습니다. 동명이인과 가릴 수 없어서, 스크립트는 그런 경우의
  수만 알려 줍니다.
- "B동 304호" ↔ "304호", "제1동 제1층 제104호" ↔ "104호", "504호(서진플로렌스)" ↔ "504호" 는 같은
  호로 봅니다.

관리자 화면의 호 목록 입력은 쉼표·공백으로 나누되 `A동`·`2층`·`지하`·`제` 같은 앞말은 뒤 호와
잇습니다. 전에는 `A동 201호` 가 `A동`·`201호` 로 쪼개져 A동·B동의 같은 호가 하나로 합쳐졌습니다
(170-4, 보강 때 명부로 복구).

## 마법 선택 (영역 찍기)

지도 왼쪽 컨트롤 줄에서 **내 위치 아래** 올가미 버튼을 누르면 영역을 만드는 모드가 됩니다.
지도를 **눌러 점을 하나씩 찍으면** 그 점들을 이은 다각형이 그려지고, 점이 3개가 되면 면이
됩니다. **첫 점을 다시 누르거나** 아래 가운데 조작줄의 `완료` 를 누르면 그 영역에 걸친 필지가
선택되고 모드에서 나옵니다. `되돌리기` 로 마지막 점을 물리고, `끄기` 로 그냥 빠져나옵니다.
`Shift`(또는 `Ctrl`)를 누른 채 완료하면 기존 선택에 더합니다.

- 조작줄은 **아래 가운데**, 요약 카드보다 위(`z-1200`)에 둡니다. 지도를 덮는 요약 카드·필지
  카드가 `z-1000` 이라 그보다 낮으면 완료·끄기 버튼이 가려집니다. 버튼은 상태에 따라
  사라지게 두지 않고 흐리게만 합니다 — 있다 없다 하면 어디 있는지 찾게 됩니다.
- 영역을 찍는 동안에는 지도를 덮는 요약 카드와 필지 카드를 치웁니다. 확정하면 모드에서
  나오므로 결과(선택 영역 카드·알림)가 바로 보입니다.

- **선에 걸치기만 해도 선택**됩니다. 영역 안에 온전히 들어오지 않아도 됩니다 — 구역계를
  잡을 때는 경계에 걸친 필지를 빠뜨리지 않는 쪽이 낫습니다. 겹침은 세 가지로 봅니다:
  한쪽 꼭짓점이 다른 쪽 안에 있거나(어느 쪽이 더 크든 잡힙니다), 변끼리 가로지르거나.
  변 교차까지 봐야 도로처럼 가늘고 긴 필지가 꼭짓점 없이 영역을 관통하는 경우를 놓치지 않습니다.
- **구역에 편입된 필지만** 고릅니다. 보이지 않는 구역의 필지는 지도에 그려지지도 않으므로
  제외합니다 — 눈에 보이는 것만 고릅니다. 구역 미지정 필지를 구역에 편입할 때는 지금처럼
  필지를 직접 클릭하세요.
- 찍은 점은 **지도 좌표**로 들고 있고 도형도 지도 오버레이로 그리므로, 점을 찍는 도중에
  지도를 움직이거나 확대해도 제자리에 남습니다. 지도를 덮는 판이 없어 그리는 중에도 지도가
  평소대로 움직입니다.
- 필지 폴리곤이 지도를 거의 덮고 있어, 필지를 누른 경우에도 그리는 중이면 선택이 아니라
  점이 찍히게 보냅니다. 이 경로가 없으면 대부분의 자리에 점을 찍을 수 없습니다.
- 판정은 **화면 좌표**에서 합니다. 폴리곤을 그릴 때 쓰는 변환(`fromCoordToOffset`)을 그대로
  써야 "그린 자리" 와 "칠해지는 자리" 가 어긋나지 않습니다. 찍은 점은 배경지도를 직접 누른
  좌표라 그대로 두고, 필지는 그릴 때처럼 `shiftLng` 로 밀어서 봅니다.
- 올가미는 네이버 지도에만 있습니다. 키가 없을 때 뜨는 Leaflet 대체 지도(`MapView.tsx`)에는
  없습니다.

선택이 생기면 **선택 영역** 카드(넓은 화면은 오른쪽 열, 좁은 화면은 오른쪽 위)가 뜹니다.
구역과 상관없이 **고른 필지만으로** 제출률과 면적 동의율을 따로 냅니다. 구역 카드와 같은
`summarizeZone` 을 쓰므로 같은 범위를 고르면 두 카드의 숫자가 맞습니다.

넓은 화면에서는 이 카드가 뜨는 동안 **구역 전체 카드를 치웁니다**. 280px 한 줄에 둘 다
쌓으면 아래 지번 검색·필지 목록이 밀려납니다. 고른 게 있는 동안 궁금한 건 그 범위의 숫자지
구역 전체가 아니므로, 선택을 해제하면 구역 카드가 다시 나옵니다. 좁은 화면의 알약 두 개는
한 줄씩이라 자리가 모자라지 않아 그대로 둘 다 보여줍니다.

제출률의 분모가 될 소유자 수는 구역처럼 저장된 값이 없어 **추정 소유자 수**를 기본으로
씁니다. 카드 아래 칸에 아는 숫자를 넣으면 그 값으로 다시 계산합니다 (선택이 바뀌면 지워지고,
저장되지 않습니다).

## 현재 데이터 상태

`public/parcels.json` 은 **VWorld 연속지적도에서 받은 실제 논현동 필지 5,509개**입니다 (2025년 고시 기준).
필지마다 지번·지목·면적(폴리곤에서 계산)·개별공시지가가 들어 있고,
그중 **4,299필지에 건축물대장 정보**가 붙어 있습니다 (세대 14,421 + 가구 9,286 = 23,707).

주택 유형: 단독주택 809 · 공동주택 408 · 다가구주택 369 · 다세대주택 342 · 아파트 52 · 연립주택 36 · 다중주택 4

**구역은 비어 있는 상태(`data/zones.json` = `[]`)** 입니다. 관리자 모드에서 `+ 구역 추가` 로
직접 만들고 필지를 편입하세요.

### 성능

필지가 5천 개가 넘어 두 가지 처리를 합니다.

- `public/parcels.json` 을 **정적 파일로 분리**해 브라우저가 직접 받습니다. 서버 렌더링 페이로드에
  실었을 때 2.6MB였던 페이지 HTML이 13KB로 줄고, 필지 데이터는 브라우저 캐시를 탑니다.
- 지도에는 **화면 안에 들어온 필지만** 그립니다. 폴리곤 객체는 한 번 만들면 재사용하고,
  화면을 벗어나면 지도에서만 떼어냅니다. 구역 미지정 필지는 **줌 17 이상**에서만 표시합니다
  (`MIN_ZOOM_FOR_ALL`). 지도 우하단에 현재 그려진 필지 수가 표시됩니다.

## 실제 지적도로 교체

```powershell
$env:VWORLD_KEY="발급받은키"
npm run import:vworld    # 논현동(법정동 1168010800) 전 필지 → data/parcels.json, data/boundary.json
npm run reseed:zones     # 구역의 PNU 목록을 새 데이터에 맞춰 정리
```

`import:vworld` 는 논현동을 감싸는 BBOX로 페이지 단위 조회한 뒤 **PNU 접두사 `1168010800`** 으로
논현동 필지만 추려냅니다. 면적은 폴리곤에서 계산하고, 지목은 `jibun` 의 부호("38 대")를 풀어서 씁니다.

VWorld 응답의 함정 두 가지:

- `properties.bonbun` 이 `"26공"` 처럼 **지목이 붙어서** 옵니다. 그래서 본번/부번은 **PNU 문자열에서만** 잘라냅니다.
- 읍면동 경계(`LT_C_ADEMD_INFO`)는 꼭짓점 47개로 단순화돼 있어, 이걸로 필지를 자르면 가장자리 실제 지번이 100건 넘게 잘려나갑니다. 그래서 경계 폴리곤은 **표시용으로만** 쓰고 필터에는 쓰지 않습니다.

`reseed:zones` 는 이전 PNU를 버리고, 구역이 비면 `scripts/reseed-zones.mjs` 의 **예시 사각 범위**로 다시 채웁니다.
실제 구역계는 고시문을 보고 앱의 관리자 모드에서 편집하세요.

샘플 데이터로 되돌리려면 `npm run gen:parcels && npm run reseed:zones`.

## 화면 구성

| 영역 | 내용 |
| --- | --- |
| 좌측 패널 | 구역 목록(색·유형·단계·필지수·면적 합계), 지도 표시 토글, 지번 검색, 선택 필지 정보 |
| 지도 | 논현동 경계(점선) + 필지 폴리곤. 구역별 색으로 채워져 범위를 한눈에 확인. 왼쪽 컨트롤 줄에 확대·축소 / 내 위치 / 마법 선택 |
| 헤더 | 데이터 출처, 지도 유형(일반/위성/겹쳐보기), 지적편집도 토글, **관리자 모드** |
| 우상단 | 범례 / 좌하단 | 마우스를 올린 필지 정보 |

### 관리자 기능

1. 헤더의 **관리자 모드**를 켠다.
2. 지도에서 필지를 클릭해 선택한다. `Shift` / `Ctrl` 클릭으로 여러 필지를 한꺼번에 선택.
3. 좌측 **구역 편집**에서 대상 구역을 고르고 `구역에 편입` 또는 `구역에서 제외`.

한 필지는 하나의 구역에만 속합니다. 다른 구역의 필지를 편입하면 기존 구역에서 자동으로 빠집니다.
변경 사항은 `PATCH /api/zones` 를 거쳐 `data/zones.json` 에 저장되므로 새로고침해도 유지됩니다.

## API

```
GET    /api/zones                      → Zone[]
POST   /api/zones  { name, type, status, color }        구역 생성
DELETE /api/zones?zoneId=…                              구역 삭제
PATCH  /api/zones  { action: "add" | "remove", zoneId, pnus: string[] }
PATCH  /api/zones  { action: "clear", zoneId }
                                       → 모두 갱신된 Zone[] 반환
```

## 배포 (Vercel)

이 앱은 정적 사이트가 아니다. API 라우트, 서버에서의 MongoDB 조회, 쿠키 인증이 있어
Node 런타임이 필요하다. GitHub Pages 로는 배포할 수 없다.

1. Vercel 에서 이 GitHub 저장소를 Import 한다 (프레임워크는 Next.js 로 자동 인식된다).
2. Environment Variables 에 아래를 넣는다. 로컬에서 쓰는 `atlas-credentials.env` 는
   저장소에 올라가지 않으므로 `MONGODB_URI` 는 반드시 여기에 넣어야 한다.

   | 이름 | 설명 |
   | --- | --- |
   | `MONGODB_URI` | Atlas 접속 문자열 (비밀번호 포함) |
   | `MONGODB_DB` | 데이터베이스 이름 (기본 `nonhyun`) |
   | `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID` | 네이버 지도 Client ID |
   | `NEXT_PUBLIC_NAVER_KEY_PARAM` | `ncpKeyId` 또는 `ncpClientId` |

3. MongoDB Atlas → Network Access 에서 `0.0.0.0/0` 을 허용한다.
   Vercel 은 고정 IP 가 없어서 대역을 좁힐 수 없다.
4. 네이버 클라우드 콘솔 → Maps 애플리케이션의 "Web 서비스 URL" 에 배포 도메인
   (`https://<프로젝트>.vercel.app`)을 추가한다. 등록하지 않으면 지도가 인증 실패로 뜨지 않는다.
5. 첫 배포 후 관리자 계정이 없다면 로컬에서 한 번 넣어둔다.

   ```powershell
   $env:ADMIN_ID="아이디"; $env:ADMIN_PW="비밀번호"; npm run seed:admin
   ```

### 참고

- 구역·명부·관리자 계정은 모두 MongoDB(`nonhyun`)에 있다. 배포본과 로컬이 같은 DB 를 본다.
- `lib/consent.json`, `nonhyun.xlsx`, `의향서*.xlsx` 는 개인정보라 저장소에 올리지 않는다.
- 새 명부가 오면 **`merge:consent`** 로 DB 를 보강한다. `import:consent` → `migrate:consent` 는 DB 를
  명부로 통째로 갈아 끼워 관리자 화면에서 고친 값(통건물 총 호수, 묶은 지번, 뺀 호)이 사라지므로
  처음 한 번만 쓴다. 자세한 규칙은 아래 [새 명부로 보강하기](#새-명부로-보강하기).
- 개발 서버를 켠 채로 프로덕션 빌드를 확인하려면 출력 폴더를 분리한다.

  ```bash
  NEXT_DIST_DIR=.next-build npm run build
  ```
